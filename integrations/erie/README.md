# 直接使用 Erie 编译器的接入实验

这项实验运行 **erie-web 1.0.1 的原始 Node 编译器**，不是 Python 模型的模拟。它只编译数据与声音队列，不启动浏览器，不播放音频。

已保存结果：[完整观察数据](../../artifacts/erie-direct/observation.json)。包来源、仓库地址、npm integrity 与下载包 SHA-256 保存在 [来源记录](../../research/erie-package-provenance.json)。来源记录中的仓库与 Erie 原作者公开仓库一致。

## 可复验的发现

比较 `[1,2,3]` 与 `[10,20,30]`，以时间映射到 0–1 秒、音高映射到 200–800 Hz。

| 配置 / 范围 | 观察 |
| --- | --- |
| 各自自动确定数值范围，单一纯音流 | 去掉非声音的 `__datum` 后，编译出的声音事件相同 |
| 相同配置，完整预渲染队列 | 队列不同：语音图例分别读出 1/3 与 10/30 作为数值范围 |
| 两组共同使用显式输入范围 0–30，纯音流 | 声音事件不同 |

任务“是否存在 ≥5 的数值”的答案分别为 false、true；总和分别为 6、60。纯音流不能单独区分，但完整队列提供了额外的语音上下文。**因此，这不是对 Erie 完整声音图表的故障证明。**

本版本中，例子的 skip 配置未阻止新 ordering/prerender 路径生成这些图例；这只是这个具体版本和配置的观察，尚未独立确认接口的预期语义，也没有向上游提交问题。

## 重跑

1. 用 Python 运行 `fetch_source.py` 下载固定版本源码；脚本校验固定 SHA-512，不执行安装脚本。
2. 在此目录运行 `pnpm install --frozen-lockfile --ignore-scripts`。
3. 从项目根目录运行 `node integrations/erie/check.cjs`。

要求支持 CommonJS 加载同步 ES module 的 Node.js 版本；实测运行时在观察 JSON 中记录（本次 v24.19.0）。四个直接依赖及所有传递版本由 pnpm 锁文件固定。

官方 npm 包的 `main` 指向不存在的 `dist/index.js`；本实验明确加载已发布的 `build/erie-web-node.js`。不修改官方包源码。这个入口问题也只是已下载固定版本的事实，不推广到其他版本。

## 输出和边界

脚本保存四个完整规范、原始音流、原始完整队列、剔除 `__datum` 的确定性比较视图、后端哈希和锁文件哈希。比较不抹掉语音，不把不同图例当作相同。纯音流按起点排序，因为原始内部流数组不一定按时间顺序排列。

断言检查三项观察，失败时退出码非零。这不是 Web Audio 渲染验证、真人听觉试验或 Erie 所有功能的覆盖审计。默认统计不与 Python 核心的穷举结果混用。

原始 Erie 代码采用 MIT 许可，保留在下载包 `LICENSE` 中；本目录桥接脚本采用项目 MIT 许可。

## 有限输入集合与汇总兼容性实验

`node integrations/erie/corpus.cjs` 从项目根目录运行，会捕获 `[1,2,3]` 三种数值、长度 3 的所有 27 个序列，分别测试自动数值范围和均值汇总。均值规范采用 [官方 Aggregate 接口](https://see-mike-out.github.io/erie-documentation/docs/data-transform/aggregate.html)。

已观察到：自动数值范围的纯音投影只有 13 类，而完整队列有 27 类；阈值 3 在纯音范围有 14 对冲突，在完整录制队列没有冲突。均值汇总的完整队列有 8 类，阈值 3 有 12 对原始输入冲突，原始趋势有 41 对、原始峰值位置有 49 对冲突；总和在固定长度集合中没有冲突。

8 类而非数学上预计的 7 种均值，来自编译结果中的浮点差异；工具严格比较记录，不把略有不同的机器参数自动当作相同。没有对此差异做人耳解释。

`[1,3,2]` 与 `[2,2,2]` 的平均值都为 2，完整录制声音和语音可以相同，但原始数据是否达到 3 的答案不同。汇总有意丢掉细节，因此结果应该报告为任务与汇总方式不匹配，不称为 Erie 缺陷。

Python 的 `compiled` 命令默认检查完整队列，输出录制反例及离线报告。其 verifier 不重新执行 Erie；重新运行本捕获脚本才会重新验证外部输入到输出的关联。
